# Prioritized animation improvement plan

These are proposed changes for a later implementation pass. No item below has been applied. Preserve all current movement speeds, collision bodies, jump displacements, projectile origins, shot/cooldown ticks, enemy decisions, damage, rescue and boss attack schedules. Presentation can change without making gameplay wait for a drawing.

## Review order and release gates for the later implementation

1. Approve the eight walking keys, contact chart and model overlay before any new export. Review full-size art and the existing in-game size; include all ten identities, especially the blue character’s existing second crest accent.
2. Fix presentation phase selection and locomotion/action continuity, then tune exposures using measured displacement. Compare with the unchanged 32-tick walk control. Faster or slower is not automatically smoother.
3. Preview complete loops, stop/restart, both facing directions, wall pressure, shoes, moving fire, air fire, zero-velocity apex holds, landing and immediate re-jump. Inspect final recovery and `last → first` boundaries.
4. Implement only the approved additional drawings. Export fixed canvases, shared scale and explicit contact/face markers; do not independently crop-and-fit every pose.
5. Prove behavior through Game Engine recorded input/replays and hash traces. Run focused native render checks across current viewports and `phone-low`; keep existing draw/memory budgets. The present study measured 13 dragon / 12 enemy draw calls in focused scenarios, not real phone GPU time.

Reference footage/exposure data would be needed to claim exact Cuphead timing. It is not needed to apply the visible principles above. All proposed ticks are our own tests, not measurements of Cuphead playback.
